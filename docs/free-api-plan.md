## 1. 目标与边界

### 要做的

- 收集中转站上**实际价 = 0** 的模型，以及 Agent 平台的免费积分（WorkBuddy / Trae 等）
- 两栏分开管理、分开排序、分开展示
- 网关支持 `free/` 模型名前缀，显式走免费池
- 平台侧支持账号池、每日签到、额度倒计时

### 不做的

- 不把免费供给混进 `rankByModel` / `summarize` / `headline`
- 不在免费池耗尽时静默回落到付费（会背着你花钱）
- 不逆向客户端的加密凭据存储
- 不做多账号批量注册 / 薅羊毛

### 三条硬边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | 免费供给在**数据入口**被切断，不是渲染层过滤 | 渲染层过滤漏一个分支就会污染「最便宜」结论 |
| 2 | 免费池耗尽 → 明确报错，回落必须显式开关 | 静默降级等于偷偷花钱 |
| 3 | 免费模型的可信门槛**不低于**付费模型 | 没人会白送，免费恰恰是最需要验指纹的场景 |

### 结构

```
免费

│   自动选站，只有你在客户端写 free/ 前缀时才会用到。        │
│                                                          │
│  ┌────────────────┬────────────────┐                     │

├──────────────────────────────────────────────────────────┤
│  （当前栏内容）                                           │
└──────────────────────────────────────────────────────────┘
```

说明条放在切换控件**上方**，两栏共用 —— 「不参与比价」这条边界对两边都成立。

### 两栏内容

| | 中转站免费模型 | 平台积分 |
|---|---|---|
| 指标条 | 可用数 / 今日消耗 / 剩余配额 / 可用率 | 已连接平台 / 账号数 / 剩余积分 / 今日已签 |
| 主体 | 表格：模型、站点、分组、配额、指纹、延迟、状态 | 卡片网格：图标、名称、连接状态、账号数、积分、进度条、重置倒计时 |
| 操作 | 刷新倍率、行内改配额上限 | 签到、账号池、刷新目录、连接 |
| 空态 | 「去站点页导入倍率，实际价为 0 的会自动出现」 | 「连接 WorkBuddy / Trae，或手动填一个额度」 |

### 路由

```
#free/relay      中转站免费模型
#free/platform   平台积分
```

`setTab()` 需要支持二级 hash（`hash.split('/')`）。默认栏：有平台进平台栏，否则进中转站栏。

### 视觉隔离（关键）

免费池如果长得像比价表，用户迟早会问「为什么最便宜的不是它」。三个手段：

1. 页面副标题写「不参与比价与自动选站」
2. 顶部浅色说明条（`alert calm`，不用警告色）
3. **免费模型表没有价格列**，改显示「配额」列 —— 表格长得不一样，就不会被当成同一类东西

## 3. 用户怎么用免费额度

两种入口，语义互补，**不冲突**。

| 入口 | 模型名 | 走哪 | 适用场景 |
|---|---|---|---|
| `/v1` | `deepseek-v4.1-flash` | 付费池 | 默认，和现在一样 |
| `/v1` | `free/deepseek-v4.1-flash` | 免费池 | 混着用，单请求级别 |
| `/free/v1` | `deepseek-v4.1-flash` | 免费池 | 整个客户端只用免费 |
| `/free/v1` | `free/deepseek-v4.1-flash` | 免费池 | 前缀幂等，剥掉即可 |

### 优先级规则（只有一条）

```
isFree = 模型名带 free/ 前缀  ||  入口路径是 /free/v1
```

**前缀只能把请求「升级」到免费池，不能降级回付费。** 所以不存在歧义：

- `/free/v1` 上请求付费模型 → `404 model_not_in_free_pool`，**不静默回落**
- `/free/v1` 上再写 `free/` 前缀 → 剥掉前缀，仍走免费池（幂等）

### 模型列表怎么返回

| 端点 | 返回 |
|---|---|
| `GET /v1/models` | 付费模型 + **带 `free/` 前缀的免费模型**（`owned_by: 'manageapi-free'`） |
| `GET /free/v1/models` | 只有免费模型，**不带前缀** |

`/v1/models` 里返回 `free/xxx` 是有意的：名字自带前缀，用户在客户端下拉里能看见、能选，且一眼知道走的是免费池 —— 符合「显式选择」原则。不带前缀的免费模型名**永远不出现在付费入口**，避免误选。

### 免费池用尽时

```json
HTTP 402
{
  "error": {
    "type": "free_pool_exhausted",
    "message": "deepseek-v4.1-flash 的免费额度已用尽",
    "sources": [
      { "name": "云雀", "resetAt": "2026-10-24T00:00:00+08:00" },
      { "name": "WorkBuddy", "resetAt": "2026-10-24T00:00:00+08:00" }
    ]
  }
}
```

把「哪个来源、什么时候重置」直接告诉用户，而不是含糊的 429。

## 4. 免费侧的决策

### 为什么不能照搬付费侧

付费侧所有供给有一个共同可比指标 —— **有效成本**。免费侧没有价格，`0 ÷ 质量` 恒为 0，除法失效。

所以免费侧用「**闸门 + 单指标排序**」，而不是加权打分。

| 层次 | 规则 |
|---|---|
| **闸门**（不达标直接排除） | 指纹不达标 / 输出截断 / 额度耗尽 / 配额窗口内超上限 |
| **排序**（通过闸门的候选） | 按跨栏偏好策略，见下 |

**质量指标不参与排序，只作闸门。** 付费侧「质量差一半成本翻倍」靠除法自然降权；免费侧成本恒为 0，只能「不达标就整个排除」，不给「便宜但烂」留位置。

### 两栏各自排序，不合并列表

| | 中转站侧 | 平台侧 |
|---|---|---|
| 主要闸门 | 指纹不符、输出截断 | 额度耗尽、会话失效 |
| 排序指标 | 剩余配额天数 | 剩余积分天数 |
| 特有风险 | 掉包（假模型） | 断供（额度没了） |

合并成一个列表会让用户看不出「这条为什么排第一」。

### 跨栏偏好（全局设置，三选一）

同一个模型可能同时出现在两栏，`free/xxx` 的默认解析按这个设置走：

| 取值 | 行为 | 适合 |
|---|---|---|
| `platform` | 平台优先，平台无可用才看中转站 | 更怕「假货」 |
| `relay` | 中转站优先，中转站无可用才看平台 | 更怕「断供」 |
| `remaining`（**默认**） | 按「预计剩余天数」降序，跨栏混排 | 让额度数字说话 |

「预计剩余天数」是唯一跨来源可比的量：

```
剩余天数 = 剩余量 ÷ 近期消耗速率
```

剩 50 积分但每天用 40 的，会排在剩 20 积分但每天用 2 的后面。

**为什么默认 `remaining`**：`platform` 会让 WorkBuddy 那种每日小额积分很快耗光；`relay` 会让掉包风险高的站拿到更多流量。按剩余天数排是把风险交给额度数字，而不是质量判断。

### 界面呈现

每栏顶部一行「当前首选」，表格一行一个模型：

```
中转站免费模型 12    今日消耗 34 次    剩余 1.2M    可用率 92%
deepseek-v4.1-flash 的首选：云雀（还剩 6 天）
──────────────────────────────────────────────────────────
模型                    首选来源   候选   配额      指纹   延迟   状态
deepseek-v4.1-flash     云雀      2 个   20/天     100%   1.2s   ●可用
glm-5                   星链      1 个   100/月     50%   2.8s   ●可疑
```

点开行能看到全部候选，以及每个候选**为什么没被选中**（额度耗尽 / 指纹 50% / 延迟 3.2s），沿用付费侧 `statusReason` 的思路。

### 手动调序

复用付费侧的**上下移动按钮**，不做权重。限制：**只能调通过闸门的候选**，不可信的拖不上去 —— 与付费侧一致。优先级放在 M2 之后。

### T1 · 中转站侧（约 3.5 天，可独立交付）

| # | 任务 | 内容 | 量 |
|---|---|---|---|
| T1-1 | 识别与打标 | `syncOffers` / `updateOfferPrice` 后，按**解析后实际价 === 0** 判定 | 0.5 |
| T1-2 | 免费池排序 | `core/rank-free.js`：闸门（指纹/截断/额度）→ 按 `freeCrossPane` 偏好排序 | 0.5 |
| T1-3 | 配额 | `freeQuota: { unit, limit, used, window, resetAt }`，网关转发时累加 | 1 |
| T1-4 | 探针权重适配 | 免费模型 `integrity` = 指纹×0.6 + 未截断×0.4 | 0.5 |
| T1-5 | 前端表格 | 模型 / 站点 / 分组 / 配额 / 指纹 / 延迟 / 状态，行内改上限 | 1 |

**技术要点**

- **判据严格用 `=== 0`，不设容差。** `0.001/Mtok` 是真的便宜，不是免费；放宽阈值会把它误判成免费，反而更糟。
- 必须在 `resolveOfferPrice()` **之后**判断，因为 `实际价 = 原价 × 分组倍率` —— 倍率为 0 时原价不为 0 但实际免费。
- 配额单位不统一，各记各的：

```js
{ unit: 'request', limit: 20,     used: 3,  window: 'day'   }
{ unit: 'token',   limit: 500000, used: 12, window: 'month' }
```

只在「预计剩余 = 剩余量 ÷ 近期消耗速率（天）」这一层收敛，才能跨单位比较。

**验收**：配一个「每天 20 次」的免费模型 → 网关用 `free/` 前缀能调 → 用一次扣一次 → 跨天自动归零 → 比价页看不到它。

## 7. 风险与回退

| 风险 | 影响 | 应对 |
|---|---|---|
| OAuth 端点拿不到 | T2b 卡住 | 退化成手动填 token，T2a 成果不受影响 |
| 配额单位换算不准 | 「预计还能撑几天」失真 | 各记各的单位，只在剩余天数一层收敛 |
| 免费流量稀释付费站样本 | 长期评分失真 | 付费站保留独立探针频率，不依赖真实流量 |
| 签到被风控 | 账号异常 | 幂等 + 失败上限 + 全程留日志，不自动重试到底 |
| 中转站把免费改成付费 | 免费池突然空掉 | 每次导入倍率后重新判定，卡片上标记「刚失效」 |

**回退原则**：T1 与 T2 互不依赖，任一可以单独上线；T2b 失败不阻塞 T2a。

## 附录 C · 设计判断记录

### C1 「免费」是三种东西，只有两种进免费池

| 类型 | 例子 | 归属 |
|---|---|---|
| 赠送额度 | 站送 5 元试用金 | **付费侧**，加「赠送」标记 |
| 免费模型 | 标价 0 或倍率 0 | 免费池 |
| 每日免费次数 | 每天送 N 次 | 免费池 + 配额闸门 |

赠送额度在经济学上和充值没有区别 —— 都是「余额有限、用完就停」，价格也是真实价格。混进免费池会让「按配额排序」失去意义。

### C2 免费模型的门槛应该更高，不是更低

没人会白送。中转站免费送模型，动机无非引流、刷量、限时促销，而对应的偷工方式恰恰是**用小模型冒充大模型**。

所以免费模型是探针最有价值的场景。「反正不要钱」是错误心态 —— 你付出的不是钱，是任务质量。

### C3 中转站免费 vs 平台积分，风险模型完全不同

| | 中转站免费模型 | 平台免费积分 |
|---|---|---|
| 谁在送 | 二道贩子，自己也可能在偷工 | 原厂（WorkBuddy / Trae） |
| 主要风险 | **掉包**、限速、随时转付费 | 封号、额度规则变、要客户端 |
| 可信基线 | 低，必须探针 | 中高，模型是真的 |
| 失效方式 | 突然下架 / 变付费 | 额度耗尽 / 签到断 |

一句话：**中转站要防「假货」，平台要防「断供」。** 解法完全不同，这是两栏分开的根本原因。

### C4 不复刻客户端的加密凭据读取

参考实现里做了 `findAppExecutable` → `deriveAtRestKey` → 解密三步，也就是**逆向桌面端的静态加密存储**。

不复刻的理由：客户端一升级就断、绕过加密存储有合规风险、每个平台一套维护成本失控。

改用 OAuth 拿 token，用项目已有的 AES-256-GCM 加密存本地 —— 零逆向、不要求装客户端、协议公开。

### C5 免费池不能按「余量」排序

余量多但没人用的站，往往质量差。应按「预计还能撑多久」：

```
score = 剩余量 ÷ 近期消耗速率    // 单位：天
```

剩 50 积分但每天用 40 的站，应该排在剩 20 积分但每天用 2 的站后面。
