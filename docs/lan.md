# 局域网访问（网关 + 面板）

默认情况下 daemon 只绑 `127.0.0.1`，同一 Wi-Fi 下的手机、平板、另一台电脑都连不上——
这是有意的：面板接口（`/api/*`）**没有账号体系**，能打开就等于能明文看到所有上游站点的 Key、
能删站点改路由。

想在别的设备上用，打开面板里的开关：**网关 → 局域网访问**。

## 打开之后是什么样

同一个端口号，两个监听器，按**绑定的网卡**分权：

| 监听 | 谁能连 | 有什么 | 靠什么鉴权 |
|---|---|---|---|
| `127.0.0.1:4319` | 只有本机 | 面板 + 网关 | 没有（本机即身份） |
| `<局域网IP>:4319` | 局域网内设备 | 面板 + `/v1`、`/free` | 面板：局域网令牌；网关：网关 Key |

- 开关**关着**时，daemon 根本不在局域网网卡上监听，别的设备连 TCP 都握不上手（不是 403，是连不上）。
- 开关**打开**后立刻生效，不用重启进程；关掉也立刻释放端口。
- 判定依据是 TCP 连接落在哪张网卡上，不是 `Host` 头——`Host` 是客户端自己填的，
  `curl -H 'Host: 127.0.0.1'` 一秒就能绕过，它只能挡浏览器那一侧（DNS rebinding）。
- 局域网入口只接受私有网段来源（RFC1918 / 链路本地 / CGNAT / IPv6 ULA），
  所以就算有人在路由器上做了端口转发，也不会当场变成「全世界都能花你余额」的开放代理。

## 警告：仅限局域网

> **仅在局域网内使用；公网部署请务必关闭。**
> 面板没有账号体系，局域网访问只靠一串令牌守门——令牌被人拿到，就等于交出全部上游 Key。
> 局域网里是明文 HTTP，同网段能嗅探到令牌。

## 在别的设备上打开面板（三步）

1. 本机面板打开 **网关 → 局域网访问**，点开关（会弹一次确认）。
2. 点 **「复制带令牌的链接」**，把链接发到手机/平板/另一台电脑（微信、备忘录、AirDrop 都行）。
3. 在那台设备上打开链接 —— 直接进面板，令牌会存成 7 天 cookie，以后打开首页就行。

也可以用令牌手动登录：访问 `http://<局域网IP>:4319/` 会出现登录页，粘贴令牌即可
（令牌在本机面板那张卡上点「复制令牌」）。

脚本/命令行访问面板接口：

```bash
curl -H "Authorization: Bearer <局域网令牌>" http://192.168.1.26:4319/api/state
```

## 网关（`/v1`）照旧用网关 Key

局域网入口的 `/v1`、`/free` **不需要局域网令牌**，它认的是网关 Key：

```
Base URL: http://192.168.1.26:4319/v1
API Key:  <网关 Key，sk-mapi-...>
```

网关 Key 在面板「网关 → API Keys」里管理。**给局域网设备单独建一把**：手机、平板
丢了或借人了，禁掉那把不影响你本机在用的。

## 重置令牌 / 关掉

- **重置**：同卡片上的「重置」按钮。已经打开的链接和 cookie 立刻失效，用新的链接重新进。
- **关掉**：再点一次开关。局域网端口立刻消失，本机面板完全不受影响。

## 不想用面板开关？命令行也行

```bash
node daemon/index.js --lan              # 强制在局域网网卡上监听（自动探测地址）
node daemon/index.js --lan 192.168.1.9  # 指定网卡
```

`--lan` 的意思是「监听器一直开着」，此时面板是否可开仍由设置里的开关决定
（开关关着 = 那张网卡上只有网关，没面板）。不传 `--lan` 时，一切由开关决定。

## 设备上开着代理？把局域网网段加进「不走代理」

这是最常见的「明明开了却连不上」，而且跟本工具无关：系统代理（或 Clash / Mihomo / Surge 的
规则模式）会把 `http://192.168.x.x:4319/` 也当成普通请求发给代理服务器，而代理服务器
**到不了你家里这个局域网地址**——表现就是一直转圈、最后超时。

本机实测：`ProxyEnable=1`、`ProxyOverride=<local>;localhost;127.*;[::1]` 时，
Chrome 打 `http://192.168.1.26:4319/` 直接卡死，而 `curl --noproxy '*'` 能通。
注意 `<local>` **只匹配不带点的主机名**，`192.168.1.26` 这种点分 IP 不在里面。

要加的条目（三台设备各自都要）：

| 设备 | 位置 | 填什么 |
|---|---|---|
| Windows | 设置 → 网络和 Internet → 代理 → 手动设置代理 → 请勿使用代理的地址 | `192.168.*;10.*;172.16.*;127.*;localhost;<local>` |
| macOS | 系统设置 → 网络 → 详细信息 → 代理 → 忽略这些主机与域的代理设置 | `192.168.*, 10.*, 172.16.*, *.local, localhost` |
| iOS / Android | 代理类 App 的「绕过局域网 / Bypass LAN」开关 | 打开 |

命令行 / agent 客户端用环境变量：

```bash
NO_PROXY=192.168.1.26,127.0.0.1,localhost no_proxy=192.168.1.26,127.0.0.1,localhost
```

顺带一句安全上的理由：面板是**明文 HTTP**，如果请求真的走了代理，
局域网令牌就等于交到代理服务器手上了。所以这里不只是「能不能用」的问题。

## 连不上时按这个顺序查

| 现象 | 原因 |
|---|---|
| 一直转圈、超时 | 开关没开；或者根本不在同一网段（先 `ping`）；或者防火墙拦了入站 |
| `ping` 不通 | AP 隔离 / 连的是访客网络 / 一方走了 VPN |
| 打开就要求令牌，但令牌不对 | 重置过令牌，旧链接失效了；回本机面板复制新链接 |
| `/v1/...` 回 401 `缺少 API Key` | 客户端没填网关 Key（面板令牌是另一回事） |
| 回 403 `局域网入口只接受局域网地址` | 来源不是私有网段（比如走了公网中转/VPN 出口） |
| 一直转圈、但本机 `curl` 能通 | 设备上的**代理**把局域网地址也劫走了，见上一节「不走代理」 |
| 卡片上写「监听器没起来」 | 探测不到局域网地址（多网卡/虚拟网卡），用 `--lan 192.168.x.x` 指定 |

## 反向验证（在另一台设备上）

```bash
# 开关关着时：404（面板路由不存在），伪造 Host 也是 404
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.1.26:4319/api/state

# 开关打开后：没令牌 401，带令牌 200
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.1.26:4319/api/state
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer <局域网令牌>" http://192.168.1.26:4319/api/state

# 网关：无 Key 401，带 Key 200
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.1.26:4319/v1/models
curl -s -H "Authorization: Bearer <网关Key>" http://192.168.1.26:4319/v1/models | head -c 200
```

自动化验收：`node .test/check-lan-gateway.mjs`（不需要真实局域网，临时数据目录）。

## 防火墙（只有拦了才需要）

Windows 会弹「是否允许访问」时勾**专用网络**。没弹就手动加一条：

```powershell
New-NetFirewallRule -DisplayName "ManageAPI LAN" -Direction Inbound -Protocol TCP `
  -LocalPort 4319 -Profile Private -Action Allow
```
